    1. 头文件保护宏（Header Guard）

        **作用**：头文件保护宏（`#ifndef`/`#define`/`#endif`）的目的是 **防止头文件被重复包含**，避免编译时出现重复定义的错误。

        ```cpp
        #ifndef TOKEN_H     // 如果 TOKEN_H 未定义
        #define TOKEN_H     // 定义 TOKEN_H，并编译以下内容
                            // （头文件的实际内容在这里）
        #endif              // 结束条件编译
        ```

        **为什么需要？**
        假设以下场景：
         - **文件 `A.cpp`** 同时包含了 `B.h` 和 `C.h`。
         - **`B.h`** 和 **`C.h`** 都包含了 `Token.h`。
         - 如果没有头文件保护，`Token.h` 的内容会在 `A.cpp` 中被包含两次，导致重复定义错误（比如重复声明 `TokenType` 枚举）。

         加了保护宏后：
         - 第一次包含 `Token.h` 时，`TOKEN_H` 未定义，所以宏生效，内容被编译。
         - 第二次包含时，`TOKEN_H` 已定义，编译器会跳过重复内容。

    2. 命名空间（Namespace）

        **作用**：命名空间用于 **避免命名冲突**，尤其是在大型项目或多库协作时。它将代码逻辑分组，让相同名称的变量/函数/类在不同命名空间下互不干扰。

        ```cpp
        namespace frontend {  // 定义命名空间 frontend
            enum class TokenType { ... };
            struct Token { ... };
        } // namespace frontend
        ```

        **为什么需要？**
        假设以下场景：
         - 你写了一个 `Token` 结构体，但另一个库也定义了 `Token`。
         - 如果没有命名空间，编译器无法区分这两个 `Token`，导致冲突。

         加了命名空间后：
         - 你的 `Token` 是 `frontend::Token`，另一个库的可能是 `backend::Token`，彼此隔离。
